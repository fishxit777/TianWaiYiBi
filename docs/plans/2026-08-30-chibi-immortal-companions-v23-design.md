# V23 雲上仙伴圖文互動設計

## 真正問題

V22 已解決暗沉，但大面積雲海背景仍缺少角色與事件，畫面像靜態型錄。使用者要的不是更多花紋，而是「仙人真的住在網站裡」：每個主要項目附近都有角色、表情、手勢或動作，讓圖與文字互相解釋。

## 方向比較

1. **六位固定仙伴（採用）**：守、造、機、局、人、音各有一位透明 Q 版仙人，在六脈、對應封印卷和拆封步驟重複登場。優點是形成品牌角色資產、風格一致、可控制載入量。
2. **每張卡生成獨立角色**：初看豐富，但角色數量會隨商品增加而膨脹，風格漂移、維護和效能成本最高。
3. **只用 CSS 表情符號或線稿**：效能最低，但無法達到使用者要求的角色插畫與修仙世界感。

## 角色陣容

- **守護脈・守雲**：女性小劍仙，青玉護盾與朱砂短劍；警覺後招手示意安全通過。
- **造物脈・鑄星**：男性小煉器師，金銅小鼎與鍛造鎚；敲擊後冒出一顆金星。
- **靈機脈・玄算**：女性小符算師，紫青法輪、符紙與靈光；掐訣時法輪輕轉。
- **破局脈・弈川**：男性小策士，摺扇與懸浮棋子；落子後得意點頭。
- **人間脈・桃夭**：女性小醫仙，藥葫蘆與仙桃；捧桃微笑並行禮。
- **傳音脈・清商**：男性小樂仙，青玉笛與音波；吹奏時音符與衣帶浮動。

角色為原創 3D Q 版仙俠公仔感，二至三頭身、完整全身、輪廓清楚；服飾沿用封卷匣的黑金、朱砂與青玉材料語言，再依六脈加入不同屬性色。全部使用透明背景、無文字、無 Logo、無水印。

## 佈局與互動

- 首屏右下由一位「守雲」在封卷匣旁招手，讓法器不再像孤立商品照。
- 六脈每張卡固定自己的仙伴，命牌與角色形成「門派徽記＋門人」兩層資訊。
- 封印目錄依主脈帶入對應仙伴，角色從卡角探身指向線索，不揭露完整概念。
- 三個拆封步驟分別由守雲、玄算、弈川演示「先看、揭示、判斷」。
- 頁尾由清商坐在雲角送客，填補大面積空白但不遮交易說明。
- 滑鼠移入、鍵盤聚焦或手機點擊角色時，觸發招手、彈跳、掐訣、點頭等 CSS 動作和一句短反應；角色按鈕不提交資料、不建立需求事件，也不改變篩選或購買流程。
- 動畫只使用 transform／opacity；`prefers-reduced-motion` 下完全靜止。離開可視區後不主動執行連續動畫，避免耗電和干擾閱讀。

## 技術與效能

- 六張透明 PNG 由 ImageGen 產生，檢查後轉為帶 Alpha 的 WebP；每張目標低於 180 KB。
- 資產放在 `static/brand/companions/`，檔名固定版本化，不依外部 CDN。
- 首屏角色可 eager 載入，其餘角色 `loading="lazy"`；重複角色共用瀏覽器快取。
- 角色互動由獨立 `v23.css` 與少量原生 JavaScript 管理，不新增前端框架。
- 管理後台、Passkey、安全頁、資料庫、付款與公開收款閘門不改。

## 驗收

- 六位角色風格、比例、光源與材質一致，透明邊緣無白底、無文字、無多餘肢體。
- 桌機 1440×900 與手機 390×844 實看首屏、六脈、目錄、拆封規則、詳情及頁尾。
- 角色不得遮住標題、正文、價格、CTA、導覽或交易提示；根頁面不得水平溢位。
- 鍵盤可以聚焦角色並看見反應；減少動態模式停用動畫。
- 自動測試、Python／JavaScript 語法、機密掃描與正式 `/healthz` 通過後才上線。
