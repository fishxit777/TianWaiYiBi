# 官網分區混合傳音設計

## 目標

在官網主要內容區塊下方加入可收合的對話入口，同時支援公開交流與客戶對守閣者的私密對話。系統必須讓訪客看得懂身分差異、保護客戶真實資料，並把審核與指定回覆集中在既有後台，而不是另建一套難維護的即時聊天室。

## 採用方案

每個公開內容區塊使用同一個「分區傳音」元件，預設只顯示一條細緻的展開列，點開後才載入資料。元件有兩個頁籤：

- `公開傳音`：所有訪客可閱讀；只有已驗證客戶可投稿。客戶投稿先進入待審核，守閣者核准後才公開。
- `私密傳音`：只有已登入客戶與守閣者可讀寫。資料庫查詢同時綁定客戶 ID 與區塊，不依賴前端隱藏。

第一版涵蓋首頁六個內容區塊與每一脈仙策的公開詳情頁；不放在付款、開通、登入、客戶權限或管理安全頁面，避免交易流程被干擾。

## 身分與顏色規則

顏色只作輔助，不作唯一識別。每位客戶以不可逆的公開客戶代碼穩定映射至一組高對比色，公開顯示自動產生的匿名稱呼，例如 `同道・7A3F`，不顯示真名或 Email。每則訊息同時具有：

- 名稱或匿名稱呼；
- 文字徽章（`守閣者`、`同道`、`指定給你`、`等待公開`）；
- 固定色頭像、名稱與左側色條；
- 維持高對比中性色的正文。

守閣者固定使用朱砂金識別。公開指定回覆只顯示匿名稱呼；真正私密內容使用私密頁籤並標示 `僅你與守閣者可見`。色彩不承載權限，後端權限才是唯一真實來源。

## 資料與權限

新增單一 `section_messages` 表：保存穩定訊息代碼、區塊鍵、可選仙策、作者類型、參與客戶、回覆對象、公開／私密範圍、審核狀態、純文字內容與稽核時間。公開查詢只回傳 `published`；私密查詢必須取得有效客戶工作階段，並固定加上 `customer_id = current_customer_id`。

訊息僅允許純文字、2 至 800 字，畫面使用 `textContent` 輸出，不解譯 HTML。客戶寫入需要 CSRF、有效客戶工作階段、狀態檢查與速率限制；公開內容若包含疑似 HTML 或網址，先拒絕並引導改成純文字。管理員核准、隱藏與回覆都使用既有 Passkey 後台工作階段、管理 CSRF 與 audit log。

## 維護方式

後台新增 `傳音對話` 工作區，集中顯示待審核公開留言、私密訊息與已公開對話。守閣者可一鍵公開、隱藏、公開回覆或私密指定回覆；不提供物理刪除，避免誤刪與失去稽核軌跡。公開留言採先審後發，因此不需要讓垃圾內容短暫出現在正式站。

所有區塊共用一套資料模型、API、模板元件、JavaScript 與 CSS；新增區塊只需加入伺服器允許清單與一個元件呼叫，避免每區複製聊天室程式。

## 介面狀態與無障礙

元件需完整處理收合、載入、空白、待審核、未登入、錯誤與送出成功狀態。頁籤、展開按鈕與表單可用鍵盤操作；焦點在展開後移至區域標題、送出後回到狀態訊息；狀態文字使用 `aria-live`。所有色票在深色背景達到可讀對比，並在 `prefers-reduced-motion` 下停用不必要動畫。

## 驗收條件

1. 訪客能閱讀已核准的公開留言，但不能投稿或讀取任何私密訊息。
2. 客戶公開投稿不會在核准前洩漏給其他人。
3. 客戶只能讀取自己的私密分區對話。
4. 守閣者能在既有後台完成審核、隱藏與指定回覆。
5. 公開畫面不出現真名、Email、內部客戶 ID 或安全設定資訊。
6. 顏色之外仍有名稱、徽章與文字說明，桌機與手機皆可理解。
7. 完整測試、機密掃描、正式站健康檢查與實際畫面驗收通過後才算完成。
