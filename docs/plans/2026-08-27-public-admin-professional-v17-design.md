# 官網與後台 V17 專業化設計

日期：2026-08-27  
範圍：天外一筆工作室官網與營運後台  
原則：保留現有品牌世界觀、金流、Passkey、備份與客戶權限邏輯；只改善資訊架構、操作安全、響應式體驗與可驗收性。

## 直接結論

V16 已完成視覺統一，但目前最大的限制已從「不好看」轉為「長頁導覽、營運判斷與可逆操作不夠清楚」。V17 採雙軌改造：官網優先降低迷路與錯誤購買預期，後台優先降低誤操作與手機漏項；所有改善都以桌機 1440×900、手機 390×844、鍵盤操作、無水平溢位與完整測試為驗收門檻。

## 官網 20 項問題與處理

1. 手機頁首只剩品牌與單一入口，六脈、流程、心訣無法快速定位；新增手機卷軸導覽列。
2. 導覽沒有目前所在章節提示；以 IntersectionObserver 標示 active section。
3. 長頁沒有閱讀進度；新增不干擾內容的頂部進度線。
4. 桌機頁首高度偏大；捲動後進入緊湊模式。
5. 客戶登入藏在頁尾；頁首新增低干擾「已購取回」入口。
6. 正式收款關閉時仍顯示「付款後開通」口吻；依伺服器狀態顯示「摘要開放／正式收款未開放」。
7. 首屏價格比可用性更醒目；將可用狀態提升為第一層資訊。
8. 手機首屏事實卡文字過小；提升最低字級與對比。
9. 沒有快速說明適合與不適合對象；新增精簡資格判斷帶。
10. 篩選結果不寫入網址；使用 query string 保存與還原。
11. 手機篩選器占用過多垂直空間；改為可橫向捲動的緊湊控制列。
12. 仙策卡「適合解決」與標籤重複；合併成單一任務標籤區。
13. 六張卡重複強調價格；收款關閉時改顯示「先看摘要」。
14. 卡片缺少交付層級訊號；補上「摘要／交付清單／傳音」狀態文案。
15. 被篩掉卡片仍可能保留可聚焦內容；同步 hidden、aria-hidden 與 tabindex。
16. 篩選無結果時沒有引導；新增可重設的空狀態。
17. 仙策詳情缺少清楚階層；加入首頁／六脈／本頁麵包屑。
18. 收款未開放時詳情仍推向結帳；改為「傳音詢問」且不產生結帳入口。
19. 詳情頁手機缺少快速回到對話的操作；加入安全的情境 CTA。
20. 頁尾信任文案假設收款已開啟；依付款狀態改為準確且可驗證的營運說明。

## 後台 20 項問題與處理

1. 手機底部導覽硬編 6 欄但已有 7 個工作區；改為完整 7 項可橫向捲動，安全稽核不再被裁掉。
2. 手機導覽字級與觸控面積不足；提高到可讀字級與至少 44px 觸控高度。
3. 切換工作區後缺乏持續的目前位置提示；強化 active 狀態與標題同步。
4. 同步訊息只是短文字；改為成功、載入、錯誤三態狀態列。
5. 載入失敗沒有就地復原；新增「重新載入」按鈕。
6. 重新整理期間按鈕仍可連點；加入 busy、disabled 與 aria-busy。
7. 同步時間不表示資料新鮮度；補上相對狀態並定時更新。
8. KPI 像按鈕但不可操作；使相關 KPI 可鍵盤進入對應工作區。
9. 流量來源只顯示數量；同時顯示百分比與可讀標籤。
10. 訂單搜尋無一鍵清除；新增清除按鈕與目前條件摘要。
11. 空訂單結果只顯示一句話；提供重設搜尋／篩選操作。
12. 手機訂單表格欄位過多；依優先級隱藏次要欄位並保留核心資訊。
13. 上下架按下即執行；改為確認視窗，清楚寫出公開影響。
14. 全站價格按下即執行；改為確認視窗並顯示前後價格。
15. 仙策編輯關閉時不提醒未儲存內容；加入 dirty-state 離開保護。
16. 對話「公開／私密」後果不夠醒目；加入即時範圍說明與警示。
17. 對話管理按鈕太小且主次不分；提高尺寸並區分公開、回覆、隱藏。
18. 已完成的付款驗收工具仍佔主要版面；完成／停用時降級為可展開的歷史驗收區。
19. 安全事件缺少快速嚴重度過濾；新增高風險優先篩選。
20. 進階安全測試工具太接近日常操作；移到二次揭露區並加上測試環境提醒。

## 視覺與互動方向

- 官網保留深靛、月金、青玉與朱砂，不更換品牌語言；增加的是導覽與狀態層，不堆新裝飾。
- 後台維持淺色營運紙面與深色側欄；危險操作只使用朱砂色，成功只使用青玉色。
- 所有可互動元素具明確 hover、focus-visible、disabled 與 busy 狀態。
- 動畫只服務方向與狀態，並遵守 `prefers-reduced-motion`。

## 驗收門檻

- 官網首頁與仙策詳情：桌機、手機均無水平溢位，導覽與付款狀態一致。
- 後台 7 個工作區：桌機、手機均可到達；手機不裁掉安全稽核。
- 所有可逆篩選保留狀態；所有高影響操作先顯示自訂確認視窗。
- JavaScript 無語法錯誤、瀏覽器 console 無新增錯誤。
- 完整測試、Python 編譯、套件一致性、差異格式與機密掃描全部通過。
- 正式站 `/healthz` 正常、`main` 與 `origin/main` 同步後才算完成。
