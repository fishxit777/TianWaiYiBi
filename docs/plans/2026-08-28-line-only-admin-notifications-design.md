# 管理通知改為 LINE Bot 設計

## 決策

天外一筆的管理員營運通知改為 LINE Bot 單一通道。固定摘要維持台北時間
08:00、12:00、20:00；高風險登入、付款、LINE 驗簽、客戶交易郵件失敗等
重大事件仍立即推播，不延遲到下一次固定摘要。

客戶付款、開通、登入碼等交易郵件維持 Email，因為它們是交付流程而不是管理員
推播。本次只取消管理員 Gmail 告警與 Gmail 營運摘要。

## 資料流

1. GitHub Actions 每日三次呼叫既有私有摘要端點。
2. 端點只建立一筆 `line` 通知佇列並立即嘗試送達。
3. 相同日期、時段與事件仍由唯一 dedupe key 防止重送。
4. 立即異常告警也只建立 `line` 通知。
5. 舊有 `email` 管理通知列不刪除，保留稽核，但不再自動或人工重試，也不再列入
   今日可處理的管理通知失敗數。

## 後台呈現

- 系統串接卡顯示「LINE 管理推播」，就緒條件是管理員 LINE 收件人與每日排程。
- 安全稽核只列管理員 LINE 告警與每日三次摘要，不再把 Gmail 當成必要通道。
- Email 交付卡仍代表客戶交易郵件，與管理員推播分開判讀。

## 安全與失敗策略

- LINE 訊息延續現有隱私清理：不含完整 Email、IP、驗證碼、Token、Cookie、密碼或
  簽章值。
- LINE 未設定時，通知保留在佇列但不增加重試次數；設定恢復後可由後台重試。
- 歷史 Gmail 列不可重新送出，避免重複告警與錯誤待辦。
- 不刪除舊資料，避免破壞稽核證據。

## 驗收標準

- 固定排程仍只有 08:00、12:00、20:00 三次。
- 每次摘要只建立一筆 LINE 通知，重跑不重複建立。
- 高風險事件只建立一筆 LINE 即時告警。
- 舊 Gmail 失敗列不會重試，也不會算入今日 LINE 待處理數。
- 客戶交易 Email 測試維持通過。
