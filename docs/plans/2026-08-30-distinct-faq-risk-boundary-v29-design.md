# 2026-08-30 V29 FAQ 分工與風險邊界設計

## 已確認的合格標準

1. FAQ 改成簡短、口語、以購買判斷與實際操作為主，不再重述正式契約、隱私與退款條文。
2. 條款與隱私保留完整、正式、可稽核的規則，新增獨立「重要風險與責任邊界」，且不得排除依法不能排除的消費者權利。
3. FAQ 桌機與手機均採單欄獨立手風琴；展開任一題時，其他題目的外框高度不得跟著改變。

## 方案比較與決策

### 採用：單欄購買導覽＋四章政策中心

FAQ 改為八個旅程式問題：適不適合、購買前看見什麼、拆封後取得什麼、能否實作商用、是否保證成功、是否非專屬、如何取回、如何求助。每題只直接回答下一個決策，需正式定義時連到政策錨點。

政策中心維持購買與服務、隱私、數位內容與退款三章，再新增「重要風險與責任邊界」。風險章節清楚區分概念與具體表達、概念示意與工程成果、合理風險揭露與法定責任，不使用「概不負責」式萬用免責。

此方案比兩欄 FAQ 更容易逐題閱讀；也比用 JavaScript Masonry 更穩定、可及且低維護。展開 `<details>` 時只推動下方內容，不存在同列卡片被 CSS Grid 拉成同高的問題。

### 不採用：兩欄 Grid 加 `align-items: start`

它雖可阻止同列卡片被拉高，但展開右欄後仍會留下大塊空白，同列下方項目也必須一起往下移，沒有真正解決獨立內容流。

### 不採用：雙獨立欄或 Masonry

雙欄可獨立伸縮，但鍵盤、螢幕閱讀器與手機的閱讀順序較難維持；Masonry 又需要額外腳本與版面重算，對八題 FAQ 沒有足夠收益。

## 內容分工

### FAQ

- 使用口語短答，不出現完整的定型化契約措辭。
- 退款、隱私與風險只說明「去哪裡看正式規則」，不複製正式條文。
- 「這是成功保證嗎？」只回答不是，並連到風險章節。

### 政策中心

- 條款：契約成立、非專屬實作、交付表達的使用限制、帳號、取回與版本。
- 隱私：蒐集、目的、受託服務、保存安全、當事人權利。
- 退款：首次揭示前後、異常處理與申請方式。
- 風險：待驗證概念、買家獨立查核、概念與表達、AI／數位視覺揭露、第三方與網路服務限制、法定權利不排除。

## 視覺與互動

- 沿用 V28 明霄雲海與玄算仙伴，不新增圖片或外部程式。
- FAQ 內容欄寬限制在適合閱讀的範圍，單卡自然高度。
- 政策風險章節使用暖金與朱砂邊界提示，但仍維持清晰正黑體與至少 16px 正文。
- 桌機與 390×844 手機均須無水平溢位；點擊第二題前後，第一題高度必須完全相同。
