# 管理員憑證本機一次性交接設計

日期：2026-08-23

## 目的

讓擁有者能取得並保存新的 256-bit 管理員密碼，同時避免明文進入
Chat、LINE、Gmail、Git、終端輸出、專案檔案或 Render 環境變數。

## 方案比較

1. LINE／Gmail 推播明文：操作簡單，但訊息歷史、鎖定畫面預覽、供應商保存與
   應用日誌都可能留下可重用憑證，淘汰。
2. 終端一次性輸出：比推播好，但仍可能進入終端捲動紀錄、錄影或工具輸出，
   不適合由自動化代理執行，保留給熟悉命令列的擁有者自行使用。
3. 本機一次性交接視窗：選定。密碼只在本機程序記憶體與 Windows 剪貼簿短暫
   出現；擁有者確認保存後，剪貼簿立刻以 Argon2id verifier 覆蓋。

## 流程

1. 本機以作業系統安全亂數產生 32 bytes，轉成 43 位 Base64url 密碼。
2. 本機以 Argon2id（19 MiB、2 次、p=1）產生 verifier。
3. 視窗顯示明文與「複製新密碼」按鈕，不寫檔、不輸出明文。
4. 擁有者把明文存入密碼管理器，勾選確認後才能繼續。
5. 確認時清除畫面上的明文，並用 verifier 覆蓋剪貼簿。
6. 將 verifier 貼入 Render `ADMIN_PASSWORD_HASH`；正式應用只驗證 verifier。
7. 新密碼登入成功後，確認舊密碼失敗，再移除 legacy `ADMIN_PASSWORD`。
8. LINE／Gmail只通知更換時間、結果與失敗原因，不含明文或 verifier。

## 失敗與逾時

- 視窗 10 分鐘內未確認即失效；若剪貼簿仍是新密碼，會清除剪貼簿。
- 關閉視窗視同取消，不變更正式環境。
- 未完成「已保存」確認前，不允許產出部署交接狀態。
- 若 Render 更新或登入驗收失敗，保留舊環境設定，不宣稱輪替完成。

## 驗證

- 單元測試驗證 43 位格式、256-bit 熵、Argon2id 正誤比對、逾時與確認閘門。
- 測試 verifier 優先，確保存在 Hash 時舊明文無法降級登入。
- 正式驗收需同時滿足：新密碼成功、舊密碼失敗、後台顯示 Argon2id 已啟用。
