# 流量訊號完整性 V2 設計

## 目標

把「工作階段」與「真人／陌生客戶」分開。系統只能證明瀏覽器工作階段，不應把它命名成真人訪客；需求判讀只使用可信基準後、排除管理測試與機器流量的公開工作階段。

## 決策

採用伺服器端分類加可信基準線，不使用 IP、瀏覽器指紋或第三方追蹤。

- 2026-08-29 00:00（台北）以前的分析事件保留於資料庫，但標記為舊基準污染，只供稽核，不進需求雷達與營運結論。
- 管理員從後台「官網預覽」進入時，必須先通過既有管理 Session；伺服器在已簽章的 Flask Session 寫入八小時預覽期限。期限內的公開頁事件統一分類為 `admin-preview`。
- 一般公開流量分成可歸因來源（搜尋、社群、轉介、LINE、Email）與未歸因來源（直接／站內）。兩者都只是工作階段，不宣稱為陌生真人。
- 明顯機器人繼續依 User-Agent 規則標記；管理測試與機器流量分開呈現。
- 仙策詳情、閱讀、意願與傳音仍是需求證據；只有首頁工作階段不構成市場驗證。

## 顯示規則

- 管理摘要使用「公開工作階段」，另列「可歸因」「未歸因」「管理測試」「機器」與「舊基準排除」。
- 仙策需求雷達使用「仙策工作階段」，不再使用「有效訪客」。
- 後台流量來源以不重複工作階段計數，不再把多個事件加總成流量。
- 少於 10 個仙策工作階段仍為資料不足；可歸因來源與深入內容行為必須交叉驗證，不能僅憑首頁瀏覽判定需求。

## 安全與隱私

- 預覽標記只由登入後的管理路由建立，不信任公開查詢參數，避免外部訪客自行逃避統計。
- 預覽期限保存於已簽章 Session，不新增永久識別碼、IP 儲存或跨站追蹤。
- 預覽入口只允許固定導向官網首頁，避免 open redirect。
- 所有 SQL 維持參數化；後台 API 仍受既有管理 Session 保護。

## 驗收

1. 未登入不能建立管理預覽狀態。
2. 登入後預覽入口會把後續首頁與仙策事件標記為 `admin-preview`。
3. 公開、管理測試、機器、可歸因與未歸因工作階段分開計數。
4. 舊基準事件保留但不進摘要與雷達。
5. 後台與 Email 不再使用「有效訪客」誤導文字。
