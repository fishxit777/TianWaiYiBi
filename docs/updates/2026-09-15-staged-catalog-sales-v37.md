# V37｜十三卷私密售前準備與逐卷發布

日期：2026-09-15。Release：`staged-catalog-sales-v37`。

## 本次授權與邊界

使用者確認先準備前十三卷，日後才決定顯價／開放購買。保留現有獨立商品頁，不再新增第二份公開目錄或打斷閱讀的售價彈窗；管理端才使用聚焦設定視窗。第十四卷不在已核准價格批次內。

價格只採本機定價草案的目標測試開價欄，不採內部洽談線。實際金額、匯入 JSON 與私密分析均留在 Git 忽略的 `_local`；本文件不記錄數字或客戶資料。暫定價格不是市場接受度、收益或實作成功的證據。

## 實作

- SQLite／PostgreSQL 都採增量新增 `prepared_price`、`sale_state`、`release_ready`。新欄位預設為空價格、`preparing`、未核對；重啟不覆蓋已保存資料，不把旧版預設價當新售價。
- 狀態區分：準備中不顯價；`price_listed` 只顯價不接受新購買；`for_sale` 仍須已上架、有效售價、內容完整性、人工核對及原有全站金流門檻全部成立。
- `commerce_status` 為首頁、詳情、公共 API、checkout 與建立訂單共用判斷；準備中的公共投影直接省略售價，不用 CSS 隱藏。公共投影不包含完整內容／私有圖／原始想法。
- 管理 API 沿用登入、異動保護及 no-store。單卷公開／開賣須明確確認；準備售價不記入操作稽核文字。十三卷批次完整驗證白名單、唯一性、金額與目前狀態後才一次提交；失敗全數回滾，XIV 不可混入。
- 管理設定與新訂單共用交易鎖；新訂單在鎖內取得當下準備售價並保存成交價快照。既有訂單仍用其 `amount` 核對付款，不回頭改價；已付費閱讀／逐卷圖片權限不受銷售狀態影響。
- 修改內容或線索發布狀態會清除人工開賣核對；原已開賣卷退回只顯價狀態，要求重新核對，不撤銷既有買家權益。
- 管理 UI 提供交付清單、成熟度、限制、內容缺口與未儲存公開效果預覽；人工核對未完成不能開賣。桌機與手機均有取消／失敗／儲存回饋，關閉未保存視窗會確認。
- 十三卷 JSON 匯入上限 16 KB，前後端均檢查完整批次；匯入只保存價格且保持準備中／未核對，不動 XIV、舊價格、訂單及圖文。

## 後續開放方式

1. 先完成每卷承諾的商業附件與交付核對；營運主體揭露、客服、發票責任、條款與退款準備另行完成。
2. 需要測試公開價格時，再由管理員選「公開售價，未開賣」並確認；此時只顯價及匿名意願，不建單。
3. 使用者明確批准正式銷售後，才逐卷核對／開賣並處理既有全站金流門檻。單一 UI 狀態不會自動解除全站安全關閉。

不增加公開留言／客戶 LINE／聊天紀錄；既有私人管理摘要與重大告警不變，不跨專案同步。
