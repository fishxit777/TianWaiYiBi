# V33 後台專項：10 項可驗證問題與修復

## 範圍

- 基準：`e642160`。僅調整後台模板、管理頁樣式與呈現用 JavaScript。
- 保留 V19 正黑體；以明亮青玉紙面延續官網品牌，不重做品牌圖。
- 不新增後台操作按鈕、登入途徑、推播工具、付款能力或 API；不改授權與安全門檻。
- 本紀錄不包含客戶資料、信箱、訂單編號、金鑰、復原碼或環境變數值。

## 問題、證據與修法

| 編號 | 修改前的具體問題與證據 | 修復及可檢查結果 |
| --- | --- | --- |
| A01 | `styles.css` 的 `.admin-login-page` 與 `.credential-setup-page` 仍使用深紫黑底；登入、Passkey、復原與目前明亮官網是不同視覺系統。 | 四個管理模板統一載入最後一層 `v33-admin.css`，青玉紙面、深墨字、相同焦點標示；V19 字體保留。 |
| A02 | 三個資料表沒有 `caption`，`.table-scroll` 沒有可聚焦區域與名稱；鍵盤使用者難以辨識或左右捲動寬表。 | 三表均有表題、`scope=col`、具名 region 及 `tabindex=0`，內容保留；橫向捲動只在表格內。 |
| A03 | `#global-price` 只有視覺上的 NT$ 前綴，沒有關聯 label；欄位目的對輔助科技不明。 | 加入 `for=global-price` 標籤與 `aria-describedby`，說明適用範圍與不會啟用收款；既有輸入限制不變。 |
| A04 | `#idea-editor` 沒有 `aria-labelledby`；對話框雖有可見標題但缺無障礙名稱。 | 加入標題 ID 與描述關聯；無需新增關閉或儲存按鈕。 |
| A05 | 製作頁沿用兩格配置卻放三張卡，1440px 下卷冊清單只占 270px、內部溢出至 555px；編輯器又混排公開／付費／內部欄位。 | 草稿與設定分欄、清單跨完整欄寬；編輯器依公開線索、拆封內容、內部製作三個 fieldset 分組。保留全部 23 欄位 ID、長度限制、required 與儲存 payload。 |
| A06 | 既有 `confirmAction` 開啟確認框後直接聚焦執行按鈕；按 Enter 容易立即確認改價、隱藏或撤銷。 | 預設聚焦既有「返回檢查」，確認仍需移動到原執行按鈕。沒有移除確認流程。 |
| A07 | 手動刷新資料的指標卻一律顯示「即時」；上次同步變舊只有相對分鐘文字。 | 改為「同步快照」，明示手動同步；超過五分鐘顯示醒目「建議更新」，不暗中新增自動請求。 |
| A08 | 製作流程、通知佇列、案件與風險狀態直接顯示 `draft`、`sent`、`reviewing` 等機器碼，事件動作亦缺中文層次。 | 增加中文呈現映射；通知 `sent` 只稱服務已接受，不假稱已閱讀。未知狀態保留代碼並標待辨識，已知事件亦保留可查核代碼。 |
| A09 | `dateText()` 與今日日期使用操作者瀏覽器時區；畫面沒有說清楚時區，營收日彙總實際又是 UTC 日期。 | 訂單、事件、同步與今日日期固定台北 UTC+8；營收維持伺服器既有 UTC 日彙總並明示日界，不改會計數字或後端查詢。 |
| A10 | 初次尚未載入的部分統計先顯示 0；載入失敗後骨架與空白仍留著，無法區分未知與零筆；刷新失敗也缺舊快照說明。 | 初始計數改破折號；分開 loading／refreshing／ready／error／stale 狀態。首次失敗移除假骨架、顯示重新載入說明；刷新失敗保留資料並明示不是最新。 |
