## 驗收標準與實作

### 1. 圖文逐次授權

- **原缺口已確認**：付費圖原位於公開static；匿名HEAD可取得200。公開HTML也曾包含被外觀遮住的真圖URL。先前金流驗收只涵蓋付款與內容頁，沒有涵蓋直接圖片請求；不表示已發生入侵。
- 75張現版／舊版付費圖（首卷3、V30的36、V31的36）移至`private_assets/brand`，移轉前後SHA-256一致；不改資料庫圖檔識別值。
- 新`private_content`路由只接受卷ID與三種固定slot，使用有效客戶／裝置session及該客戶paid訂單查詢授權。檔案解析限制私有根目錄與安全格式，不能傳任意檔案路徑。
- GET／HEAD／Range／條件請求皆先授權；不傳304或部分圖片，不提供ETag／Last-Modified，設定no-store、no-referrer。舊static命名空間與任何已被商品引用的static圖皆拒絕，防止舊建置工具意外重建後再曝光。
- 公開首頁／封印詳情移除真付費圖URL；編輯器只接受已存在的私有素材識別路徑；建圖工具拒絕輸出至public static。已購圖片內容與原圖雜湊相符。
- 每次讀取客戶session也重新驗證對應裝置Cookie、客戶歸屬、撤銷與信任期限。短效登入碼使用原子條件UPDATE及rowcount，並行請求只能成功一次。

### 2. 專案獨立

- 天外自有模組、資料表、佇列、來源封鎖與告警狀態；工作流程固定本案網域，沒有跨repo dispatch、跨案import、其他專案憑證fallback或自動更新。
- 萬語通參考基準是2026-09-13唯讀工作樹（HEAD206bc80，含既有未提交變更），不是全部已部署功能的保證。採用重大事件即時告警／例行摘要；不採用原始路徑與自由文字推播、舊認證相容入口或不可靠記憶體去重。
- 保留天外既有Passkey、復原與備份防護；雲端秘密的實際值是否重複、帳號權限及代理鏈未讀取核對，不偽稱已證明完全物理隔離。既有合法共用金流特店政策未變更。同供應商故障／帳號配額仍可能共同影響服務。
- 未來只有使用者明確要求同步或仿照才做下一次獨立移植，單案改動不等於另一案授權。

### 3. 私人LINE告警與故障處理

- 僅允許私人管理user ID；不接受群組／聊天室收件人。高／重大告警以固定事件類別、合法事件參照、時間、有限處置與遮罩IP組成，不帶客戶／訂單識別、原始path/query/detail/UA或付費內容。
- 通知先入庫、原子認領及60秒租約、成功持有claim才可更新結果。配額使用資料庫條件更新，跨worker有效：固定5分鐘最多10次告警、固定小時60次；摘要使用獨立配額3／5分鐘、6／小時。
- 穩定UUID重試鍵；首次起最多5次嘗試、最早1／2／4／8分鐘退避，23小時後停止使用該重試鍵；收件人或channel token指紋改變則停止。沒有存放原始token或收件人於新payload。
- 第五次claim後程序崩潰，租約到期會標記retry_exhausted並結束，不覆蓋有效租約或讓舊worker回寫成功。舊版自由文字payload保留稽核，不重送。
- 自動重試**只沿用既有08:00／12:00／20:00摘要工作**，一次最多10筆且有短時間預算；next_attempt是最早可重試時間，不代表有每分鐘排程。可能等到下一次摘要；永久失敗或超窗需管理員處理。
- LINE回覆2xx或有accepted參照的409僅代表API接受，不代表手機送達／真人已讀。後台重試文案已區分。此版本未另建Codex/GitHub高頻排程、不恢復客戶留言／聊天／客戶LINE webhook。

## 隔離驗證與修正循環

- 第一輪：新增存取測試先證明缺口存在；短碼／告警也先有失敗測試。修正測試中不合法的合成狀態值後，再按真實schema驗證，不放寬授權要求。
- 第二輪：獨立程式複查抓到「末次通知claim崩潰」終態缺口，已加2項回歸；全套曾因舊版本字串及舊通知狀態／匿名代碼期待失敗，已改為V32與更嚴格的新隱私規則。
- 第三輪：一般全套240 passed、PostgreSQL專用測試在一般環境跳過5項；另於全新、只綁loopback的PostgreSQL17.11執行5項全部通過，包括兩真連線同時初始化、舊schema遷移、通知CAS與登入碼併發。兩worker啟動DDL以本案交易層級advisory lock序列化，適用交易池而非session lock。
- 本機Browser1440×960與390×844：13張卡、0水平溢位、0破圖、0頁面JS錯誤、0公開結帳連結、0付費圖片URL；合成買家三張图皆正常、撤權後三張皆404。截圖與合成資料只在忽略的本機QA目錄。
- Python compileall、主要JavaScript syntax、pip check、直接7個鎖版依賴查核（已知漏洞0）通過。直接依賴結果不包含所有間接依賴或正式環境套件。
- 未操作正式帳號／付款／備份；沒有使用真客戶資料或外寄通知。測試fixture先清除可能继承的正式資料庫與服務設定。測試PostgreSQL均已停止。

## 尚不能聲稱的事

- 已購買者仍可能截圖、重畫、轉述；既有HTML浮水印不是圖內個人化浮水印，也不是DRM。已下載的副本無法撤回。
- Render真實代理鏈對傳入XFF的處理尚未實測，不因本輪補強宣稱IP可作可靠唯一身分；沒有盲改hop數導致誤封管理員。
- 私人LINE正式收訊與收件身分仍須正式證據，模擬2xx不是實際手機收到。沒有為驗證觸發未授權登入、暴力測試或重新設定憑證。
